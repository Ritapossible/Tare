# Sellers

Two x402 data sellers on **two separate public HTTPS origins**, Kite **testnet**, 0.001 pieUSD per call.

| Seller | Payload | Prose | Rows |
|---|---|---|---|
| A (short and dirty) | `data/a.json` | "Delivered one thousand two hundred forty unique records, fields id and ts, no nulls." | 1240 rows, 860 unique ids, 40 `ts: null` |
| B (clean) | `data/b.json` | "Delivered two hundred records, fields id and ts, no nulls." | 200 rows, 200 unique ids, no nulls |

Payloads are generated by `generate.mjs` (deterministic). `npm test` fails if the committed files drift.

## How a seller is built

`wrapper/` is the Kite x402 TypeScript Express template, copied **unchanged** from
[`gokite-ai/kite-x402-services`](https://github.com/gokite-ai/kite-x402-services) at commit
`893a27509648b660bbba626b0da59619a94f04ab` (`templates/typescript-express`, Apache-2.0, see
`wrapper/LICENSE`). Every request under `/v1/*` is paid, then proxied to `UPSTREAM_URL`.

The upstream is this public repo on raw GitHub, pinned to the tag `sellers-v1` so the bytes (and
therefore the body hash) never change under a seller.

> **Path quirk.** The template builds the upstream URL with `new URL("/<path>", UPSTREAM_URL)`, and
> a leading `/` throws away any path inside `UPSTREAM_URL`. So `UPSTREAM_URL` must be the bare host
> `https://raw.githubusercontent.com` and the full file path goes in the buyer URL.

> **Mainnet default.** The template uses **mainnet** when `KITE_NETWORK` is unset. Always set
> `KITE_NETWORK=testnet`, and run `scripts/seller_probe.mjs` before any payment.

## Deploy (Render, free tier) — do this twice

You need one wallet address to receive payments (`PAY_TO`). Any EOA you control works; it does not
need funds. Both sellers can use the same `PAY_TO`.

For **seller A**, then again for **seller B**:

1. Render → New → Web Service → connect `Ritapossible/Tare`.
2. Name: `tare-seller-a` (then `tare-seller-b`). Each name becomes its own origin:
   `https://tare-seller-a.onrender.com`, `https://tare-seller-b.onrender.com`.
3. Branch: the branch that holds `sellers/wrapper`. Root Directory: `sellers/wrapper`.
4. Runtime: Node. Build command: `npm ci --include=dev`. Start command: `npm start`.
5. Environment variables:

   ```
   KITE_NETWORK=testnet
   PAY_TO=0x<your receiving address>
   UPSTREAM_URL=https://raw.githubusercontent.com
   PRICE_USD=0.001
   NODE_VERSION=22
   SERVICE_DESCRIPTION=Tare demo seller A (testnet)      # "... seller B ..." for B
   ```

6. Deploy. Render sets `PORT`; the template reads it.

Fly.io or any host with public HTTPS also works. Localhost and browser-gated tunnels do not: Kite
Passport calls the seller from its servers.

## Buyer URLs

```
Seller A: https://tare-seller-a.onrender.com/v1/Ritapossible/tare/sellers-v1/sellers/data/a.json
Seller B: https://tare-seller-b.onrender.com/v1/Ritapossible/tare/sellers-v1/sellers/data/b.json
```

Replace the hosts with whatever Render gives you, then write both into `sellers.json` at the repo root.

## Verify before paying (no money moves)

```
node scripts/seller_probe.mjs "<seller A url>" "<seller B url>"
```

Both must print `RESULT : ok — testnet pieUSD, 0.001 per call`, and the probe fails if the two
URLs share an origin.

## Cold starts

Render's free tier sleeps after ~15 minutes idle and the first request can take ~1 minute. Before
running `kpass` (and before recording the video) wake both sellers:

```
curl https://tare-seller-a.onrender.com/healthz
curl https://tare-seller-b.onrender.com/healthz
```

## First paid call (human, once)

Follow `scripts/kite_check.md` and run `execute` against **seller B**. Paste the full raw output into
`MEMORY.md` and the hash into the README. If there is no hash, write "no hash returned".
